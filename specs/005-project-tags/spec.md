# Feature Specification: 项目与标签——给任务归类，并按类统计

**Feature Branch**: `005-project-tags`

**Created**: 2026-11-09

**Status**: Draft

**Input**: User description: "1.加一个创建项目的功能,可以对任务进行分类。 2.项目可以支持像流程图或者思维导图的功能，方便跟进，比如一个节点做完了，进入下一个节点，节点可编辑。 3.看板模块优化：首先是分类及其具体事项，方便区分重点项目、部门内务、协同项目；然后是数量统计，比如有2个任务都是写稿子，通过打标签，我在年度统计的时候可以直接看到一年/月/季度写了多少篇。"

## 背景与切分

用户一次提了三件事：**项目分类**、**项目内节点流程图**、**复盘面板按分类与标签计数**。

三件事都要求「任务能归类」这一块共用的数据地基，但彼此不能一个 PR 做完（宪法 I：一个 feature 只做一件事，价值要能一句话说完）。因此切分如下：

| 编号 | 范围 | 状态 |
|---|---|---|
| **005（本 feature）** | 单层项目 + 标签 + 复盘面板按项目/标签计数 + 月/季/年预设 | 本轮 |
| 006（另议） | 项目内节点推进图（节点可编辑、完成一个进下一个） | 依赖 005 的项目实体，排队中 |

一句话价值：**「这件事属于哪个项目、打了什么标签；一个月/一季/一年到底写了多少篇，一眼看到件数。」**

### 为什么流程图放到 006（写清楚，避免看起来是漏做）

1. 节点图必须先有「项目」这个实体，否则节点挂在哪里、推进给谁看都没有主。005 正好把项目立起来。
2. 节点图与推进语义（前置节点没完成能不能进下一个、并行分支怎么算、回退怎么算）是独立的一整套规则，塞进 005 会让「归类+计数」这条主线失真，也让验收无从判断。
3. 宪法 `I` 明确禁止「看板/甘特视图」。节点图是否越界，需要单独一次判定（收窄成只读推进视图，或正式修订宪法到 v1.1.0），这个判定不该夹在归类功能里顺手做掉。

## Clarifications

### Session 2026-11-09

- 问：项目要不要支持父子层级（多级分类）？→ 用户未指定；按宪法 `I`（禁止多级分类）取**单层**：一个任务最多归属一个项目，项目本身不能再有上级项目。
- 问：标签与项目的关系？→ **正交**。项目回答「归谁管」，标签回答「是什么活」。一个任务可以「属于重点项目 A」并同时打「写稿」「对外」两个标签。
- 问：统计口径里「篇」是什么？→ 就是既有口径里的**一件完成**（有完成时刻、未删除）。不新增「数量」字段，避免「一条任务写 3 篇」这种二义性。
- 问：删除项目怎么办？→ 只做**归档**，不物理删除；已归档项目的任务保留归属，历史统计仍按原项目计。
- 问：用户未回答的三个范围问题如何处理？→ 按本文件 `## 决策记录` 的 D1–D6 自行定夺，并在实现前告知用户。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 把任务归到项目，回顾时按项目看产出 (Priority: P1)

我手头同时推进「重点项目 A」「部门内务」「协同项目 B」三摊事。我先把这三个项目建出来，然后把每天记下的事归到对应的项目上。到月底想汇报时，我在复盘面板里切到「按项目」，直接看到每个项目这个月各完成了多少件，点进去就是那几件的清单。

**Why this priority**: 它自己就能用——只要「建项目 + 归任务 + 按项目计数」三步通了，汇报场景就成立，标签和季度预设都可以晚一步。它也是 006 节点图的地基。

**Independent Test**: 空库起手，建 2 个项目、记 4 件事各归一个项目、完成其中 3 件，然后在复盘面板「按项目」分组里看到 2 行、件数 2 与 1，点任一行能看到明细。

**Acceptance Scenarios**:

1. 库里有 3 个未归档项目、本月完成 7 件（重点项目 A 4 件、部门内务 2 件、协同项目 B 1 件）；打开复盘面板切「按项目」、区间取「本月」；列表按件数降序显示 4 / 2 / 1，合计 7，与结论句里的件数一致。
2. 一件任务当前属于「部门内务」；把它改归「重点项目 A」；该任务在旧项目下消失、在新项目下出现，两边的件数同时变化，明细里不重复出现。
3. 一件已完成任务没有任何项目；「按项目」列表里它出现在最后一行「未分类」下，且「未分类」行始终存在，即使只有 0 件。

---

### User Story 2 - 用标签数「这类活干了多少」 (Priority: P2)

半年下来我写了很多稿子，但它们分散在不同项目里。我给每条写稿的任务打上「写稿」标签，到年底想知道「今年一共写了多少篇」：切到「按标签」，区间取「本年」，一眼看到写稿 38 篇、汇报 12 篇、评审 9 篇。

**Why this priority**: 标签是跨项目的横切维度，能把「同一类活分散在不同项目」的情况聚起来。没有它，项目维度只能回答「哪个项目忙」，回答不了「我今年产出结构是什么」。

**Independent Test**: 造 5 件写稿任务（分属 2 个项目）与 3 件汇报任务，打完标签切「本年 → 按标签」，看到写稿 5、汇报 3，点写稿能看到 5 条明细。

**Acceptance Scenarios**:

1. 一件任务打了「写稿」与「对外」两个标签；「按标签」里它在两行各计一次，列表顶部注明「同一件事打了多个标签会各计一次」。
2. 一年里写了 38 篇带完成时刻的稿子、另有 2 篇没留完成时刻；「写稿」行显示 38，旁边以小字显示「另有 2 件没留完成时间」。
3. 打标签时输入了一个已存在的标签名（大小写、前后空格不同）；直接复用该标签，不产生第二个同名标签。

---

### User Story 3 - 月/季/年一键切换，回答「这个季度呢」 (Priority: P3)

汇报口径经常变：周报看 7 天、月报看本月、季度复盘看本季、年终看本年。我不想每次都手输起止日期。

**Why this priority**: 预设是既有能力的延伸（区间查询已经支持任意起止），成本低、收益直接；但它不是功能成立的前提，去掉它前两个故事照样可用。

**Independent Test**: 打开复盘面板，依次点「本月 / 本季 / 本年」，起止日期分别落在当月 1 日到今天、当季首日到今天、当年 1 月 1 日到今天，且件数随之变化。

**Acceptance Scenarios**:

1. 日期是 2026-11-09（周一），点「本季」→ 区间显示 2026-10-01 至 2026-11-09；点「本年」→ 2026-01-01 至 2026-11-09。
2. 今天是 2027-01-01，点「本季」→ 2027-01-01 至 2027-01-01（单日），页面不报错。
3. 手动改过起止日期后，预设按钮全部取消选中；再点「本月」回到本月区间。

---

### Edge Cases

- 空库：没有任何项目与标签。复盘面板「按项目 / 按标签」显示空态，并给一个「去建第一个项目」的入口。
- 项目名重复（含仅大小写不同、首尾空格不同）：拒绝创建，提示已存在，不自动合并。
- 项目名超长（>20 字）或为空：拒绝并提示。
- 标签名重复：不新建，复用既有的；标签名首尾空格被裁掉，内部空格保留。
- 标签名超长（>16 字）或为空：拒绝并提示。
- 一个任务打第 11 个标签：拒绝并提示上限 10 个。
- 删除标签：需要二次确认；确认后从所有任务上摘掉该标签，任务本身不受影响。
- 归档项目：项目从选择器里消失（可展开「已归档」找回），任务的归属保留；复盘面板的历史区间仍按该项目计数。
- 归档项目后又取消归档：回到选择器，历史计数不变。
- 已删除（软删）的任务：不计入任何项目或标签计数；它占用的标签关系在统计里不可见。
- 完成但没留完成时刻的任务：计入该标签/项目的件数，但不计入时间分布，并在该行以「另有 N 件没留完成时间」单独说明。
- 一件任务多个标签：每个标签各计一次；页面必须说明「同一件事会各计一次」，且「各标签件数之和」不等于「去重后的件数」。
- 区间内某项目 0 件：仍显示该行（0 件），不做隐藏，否则「这个月没动重点项目 A」看不出来。已归档且 0 件的项目除外。
- 起止跨年（如 2025-12-20 至 2026-02-10）：「本年」「本季」预设不受影响；自定义区间照常。
- 起止同一天：计 1 天，件数为当天的完成数。
- 结束日期晚于今天：按今天截断并提示，与既有行为一致。
- 时间边界：完成时刻按本地日期归日，23:59:59 与本日 00:00:00 均属当天。
- 项目数量多（30 个）且区间长（1 年）：「按项目」列表超过 12 行时折叠，提供「展开全部」。
- 快速连点预设：不出现串号结果，不闪烁空态。
- 应用在别处（记录面板/托盘）刚改过归属：复盘面板下次打开时看到新归属（不缓存旧分组）。

## Requirements *(mandatory)*

### Functional Requirements

**项目**

- **FR-001**: 用户 MUST 能创建项目，只需一个名称（1–20 字，首尾空格裁掉）；名称重复（忽略大小写与首尾空格）时拒绝并提示，不自动合并。
- **FR-002**: 用户 MUST 能重命名项目；重命名后所有既有归属立即显示新名称，历史统计口径不变。
- **FR-003**: 用户 MUST 能归档项目，并能从「已归档」里取消归档；归档不是删除，任务的归属关系保留。
- **FR-004**: 用户 MUST 能把一个任务归到一个项目，或清空归属；一个任务最多一个项目（单层，不做父子项目）。
- **FR-005**: 系统 MUST 在复盘面板的项目分组里恒定显示「未分类」一行（0 件也显示），承接没有项目的完成件。

**标签**

- **FR-006**: 用户 MUST 能创建标签，只需一个名称（1–16 字，首尾空格裁掉）；名称重复时复用既有标签，不新建第二个。
- **FR-007**: 用户 MUST 能给一个任务加上或去掉标签，单个任务最多 10 个标签；超过上限时拒绝并提示。
- **FR-008**: 用户 MUST 能删除标签，删除前需二次确认；删除后该标签从所有任务上消失，任务本身与其他标签不受影响。
- **FR-009**: 系统 MUST 在任务所在的列表行上显示其项目与标签，且不因标签过多而把行高撑坏（超过 3 个时以「+N」收拢）。

**统计**

- **FR-010**: 复盘面板 MUST 提供「按项目」与「按标签」两个分组视图，每个分组按件数降序排列，并显示件数与占区间总数的比例。
- **FR-011**: 分组列表 MUST 支持点击某一行下钻，只看该行对应的完成件明细；下钻语义与既有时间桶一致（再点一次取消）。
- **FR-012**: 复盘面板 MUST 增加「本月 / 本季 / 本年」三个预设，区间为「当期首日 → 今天」；与既有 7/30/90 天预设并存，点任一预设后其余预设取消选中。
- **FR-013**: 分组计数 MUST 只统计「已完成 + 未删除」的任务；同一任务打了多个标签时，每个标签各计一次，页面 MUST 说明这一点。
- **FR-014**: 完成但没留完成时刻的任务 MUST 计入其项目与标签的件数，并在对应行以「另有 N 件没留完成时间」单独标注；它们不进入时间分布。
- **FR-015**: 已归档项目 MUST 仍出现在其有数据的区间统计中；在选择器里默认折叠，可展开找回。
- **FR-016**: 复盘面板的两种分组视图 MUST 为空态提供出口（去建项目 / 去给任务打标签），不得只显示一片空白。
- **FR-017**: 归属与标签的变更 MUST 立即在复盘面板生效，不得缓存上一轮分组结果。
- **FR-018**: 复盘面板与分组计数 MUST 保持只读：打开、切换区间、下钻、展开都不写库、不留快照、不写本地存储。

## 兼容边界

冻结项（本 feature 不得改动，改动即视为越界）：

- 既有 17 条 IPC 命令的名称与入参顺序、`Task` / `DayView` / `Settings` / `StatsRaw` 的 serde 字段名。本轮只允许**新增**命令与**新增**字段（新字段必须可空、旧数据缺省合法）。
- 既有区间语义：`get_stats` 的起止为闭区间、结束晚于今天时截断、天/周/月桶的聚合规则、`done_at IS NULL` 不计入时间分布。
- 既有复盘面板行为：单次查询、串号防护、失败保留上次结果、`Esc` 关闭、只读。
- `capabilities/default.json` 15 项不增不减（本 feature 全是本地数据库操作，不给任何新权限）。
- 顺延规则（`push_to_tomorrow` / `back_to_inbox` / 结算）与 `NOTICE_WINDOW_MIN` 一字不改：归类是标签，不是状态，不参与顺延判断。
- 解析契约：一句话录入 `parseCapture` 的规则不变；本 feature 的输入框中出现的「#标签 / @项目」写法若与既有解析规则共存，必须由用户在界面上明确触发，不得让录入行为猜测。

## 数据影响

- **DDL**：新增两张表（项目、标签）与一张关联表（任务↔标签），`tasks` 增一列（可空的项目归属）。全部 `CREATE TABLE IF NOT EXISTS`，新增列前先判断列是否存在。
- **迁移前置**：本轮**必须**先落地 `meta.schema_version`（当前为 0），迁移在单事务内完成：写版本号 → 建表 → 补列。任何一步失败整事务回滚，库回到迁移前。
- **不许做的事**：不改写、不删除任何既有行；不给既有列改类型；不做「整理/去重/归档」这类静默动作。
- **行数**：迁移前后 `tasks` / `meta` / `day_notes` 行数必须完全一致；新增表在迁移后为空。
- **旧库能否直接打开**：能。缺表缺列由幂等迁移补齐；迁移前的库（版本 0）与迁移后的库（版本 1）都能被同一份代码打开。
- **回滚方式**：迁移前由用户手动备份库文件（或应用在迁移前自动复制一份 `suoji.db.pre-005`）；回滚 = 把备份放回。迁移不改既有行，因此「把库放回」即可完全复原。
- **统计查询**：只读，不建新索引以外的结构变更（是否新建索引由实现阶段决定，索引不属于用户数据）。

## 双语影响

- 新增 UI 文案（zh / en 成对，同一提交）：项目相关（标题、新建、重命名、归档、取消归档、已归档、未分类、项目名占位、重名提示、超长提示、删除确认），标签相关（标题、新建、添加、移除、上限提示、删除确认、复用提示），分组相关（按项目、按标签、各行件数、占比、未留完成时间小计、多标签说明、空态与出口），预设相关（本月、本季、本年）。
- 既有 key 一律不改名、不删除。复盘面板里既有的 7/30/90 天预设、时间桶标题、脚注文案保持不变。
- 应用内帮助（`content.zh` / `content.en`）各补一段：项目与标签怎么用、为什么「各标签件数之和」会大于总件数。
- README（中英各一）功能列表各补一节「分类与计数」，与帮助文案口径一致。
- 文案里出现的数字与单位（件、篇、N）必须与既有统计文案同口径，不得出现「篇」与「件」混用。

## 不可破坏的不变量

- **宪法 I（一件事）**：本 feature 只做「归类 + 按类计数」。不含多级分类、不含拖拽排序、不含批量操作、不含子任务树、不含节点推进图（006）。任何「顺手做个看板」的改动都越界。
- **宪法 II（数据唯一副本）**：迁移必须单事务、可回滚、不改既有行；任何丢数据的路径都是最高优先级缺陷。
- **宪法 III（本地优先）**：不新增网络调用、不新增依赖、不引入账号。
- **宪法 IV（IPC 最小）**：只加必需命令，命令数与权限数都要在 plan 里逐条给出理由；前端只能经由既有单一调用网关访问后端。
- **宪法 V（双语成对）**：任何新增文案缺一侧即视为未完成；缺 en 会直接把 key 名显示给用户。
- 只读不变量：统计面板任何操作都不产生写入（打开、切换、下钻、展开、折叠）。
- 口径不变量：统计件数 = 有完成时刻的完成件；未留完成时刻的单独计数，绝不伪造日期。
- 幂等不变量：迁移跑一次与跑十次结果相同；同一任务重复打同一标签不产生重复关系。

## Key Entities

- **项目（Project）**：名称（唯一，忽略大小写）、是否归档、创建与更新时间。单层，没有上级项目。归档后仍参与历史统计。
- **标签（Tag）**：名称（唯一，忽略大小写）、创建时间。与项目正交，可以跨项目复用。
- **归属关系（Project Assignment）**：任务 ↔ 项目，最多一条；可为空（未分类）。
- **标签关系（Tag Assignment）**：任务 ↔ 标签，最多 10 条；去掉即删除关系，不影响任务。
- **分类计数（Class Count）**：区间内某项目或某标签的完成件数、未留完成时刻的件数、占区间总数的比例。它由既有完成记录派生，不单独存储。
- **区间预设（Range Preset）**：7/30/90 天（既有）与本月/本季/本年（新增），只是起止日期的快捷计算，不持久化。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 从打开应用到说出「本年的写稿标签有几件」，不超过 3 次点击（打开复盘 → 点「本年」 → 点「按标签」），且件数在 1 秒内可见。
- **SC-002**: 任一项目行或标签行的件数，与其下钻明细的条数完全相等（自动化断言，抽样 10 组，0 偏差）；且「未留完成时刻小计」与总件数之差等于该差值。
- **SC-003**: 新建一个项目并给一件任务完成归属，全程不超过 5 次点击、2 次输入。
- **SC-004**: 在 500 件任务、30 个项目、50 个标签、区间 1 年的条件下，切换到「按项目 / 按标签」到列表可读的时间不超过 500 毫秒。
- **SC-005**: 升级前，库中 `tasks` / `meta` / `day_notes` 的行数与内容指纹被记录；升级后三者行数与指纹逐表一致（0 行变化），新表初始为空。
- **SC-006**: 升级失败时，把迁移前备份放回即可完全恢复（人为注入一次失败验证：库可被旧版本读回，行数与升级前一致）。
- **SC-007**: 依赖零新增：依赖清单与锁文件改动行数为 0。
- **SC-008**: 断网状态下，归类与按类计数全部可用（0 网络请求）。
- **SC-009**: 打开复盘面板、切换区间、下钻、展开折叠全部完成后，库文件指纹与打开前一致（只读验证，0 写入）。
- **SC-010**: 3 名真实用户各用 1 分钟，能独立完成「建一个项目并把 1 件任务归进去」，无需口头指导（成功率 3/3）。
- **SC-011**: 新增文案中英成对；切换语言后页面 0 处残留 key 名、0 处占位符错配。

## Assumptions

- 用户已有「完成时刻」概念（002 起就区分「有完成时刻」与「未留完成时刻」），本 feature 沿用，不重新定义。
- 用户用中文（zh）为主，但所有新增文案必须有 en 版本；不存在「只做中文」的例外。
- 项目数量级为个位数到几十，标签为几十；不为万级标签做过早优化。
- 单层项目足够表达用户的「重点项目 / 部门内务 / 协同项目」三分类；需要层级时，用标签区分（如「重点项目」项目 + 「对外」标签），而不是父子项目。
- 「季」按自然季度（1–3、4–6、7–9、10–12 月），不按财年。
- 任务归类只影响组织与统计，不影响顺延、收件箱、结算这些既有行为。
- 用户愿意在升级前手动备份，或接受应用自动保留一份迁移前副本。

## 决策记录

- **D1 单层项目**：宪法 `I` 禁止多级分类，因此项目只做单层；用户若要「重点项目 A 下的子项目」，改用「项目 + 标签」两个正交维度表达。
- **D2 本轮不做节点流程图**：依赖项目实体，且「节点推进」是独立规则集，另立 006；同时宪法 `I` 对「看板/甘特视图」的禁令需要在 006 开工前单独判定（收窄为只读推进视图，或正式修订宪法到 v1.1.0）。
- **D3 先落 `schema_version`**：AGENTS.md 明确「`schema_version` 落地前不写 `ALTER TABLE`」，因此本 feature 的第一步就是迁移基座，业务改动排在它后面。
- **D4 标签自由文本、按名去重**：不做标签层级、不做标签管理大页面；大小写与首尾空格归一后再判重。
- **D5 统计口径沿用 002/003**：件数 = 有完成时刻的完成件；未留完成时刻的单列，不伪造日期，也不进时间分布。
- **D6 项目只归档不删除**：归档保留历史归属与历史计数；标签可删除（二次确认），因为标签是横切标注，删掉不影响任务本身的存在。
- **D7 用户未回答范围问题**：`/speckit.specify` 阶段曾就「先做哪一件 / 宪法冲突怎么处理 / 迁移是否前置」提问，用户选择直接继续，故按 D1–D3 自行定夺；若与预期不符，在 `/speckit.plan` 之前提出即可，改 spec 的成本最低。
