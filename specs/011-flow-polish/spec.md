# Feature Specification: 流程与视图打磨（011-flow-polish）

**Feature Branch**: `adopt/spec-kit`
**Created**: 2026-11-10
**Status**: Implemented
**Input**: 用户 5 条反馈：① 首页分组头能跳到项目进度；② 项目进度里的任务要有和首页一样的操作（设日期等）；③ 打开复盘/项目进度后点「今天/收件箱」没反应、关闭不明显；④ 右击归类时不要单独一个输入框，直接在已有项目/标签后面放 `+`；⑤ 总览里「有几件没做」要能看明细，并支持鱼骨之外的其他总览方式。

## 用户故事

### US1 — 从首页走到项目（P1）
今天列表按「项目 · 步骤」分组。分组头右侧现在有一个箭头按钮：点它直接进项目进度页，且已经选中这个项目。
**Why this priority**：这是「看到一件事 → 想弄清它在项目里的位置」最短的一条路；没有它，用户要么记得项目名，要么在项目页里翻胶囊。

### US2 — 项目里的任务和首页一样能操作（P1）
项目进度里列出的任务行换成与首页同一个行组件：勾选、点标题改名、右击菜单（改日期、设截止日期、挂/摘步骤、移到明天、回收件箱、不做了）、DDL 徽标、项目/标签徽标全部一致；任何操作后项目面板自行重读，不要求用户手动刷新。
**Why this priority**：同一个数据在两处呈现却只有一处能改，是最容易让人怀疑「是不是没保存」的裂缝。

### US3 — 浮层要么明确关得上，要么被导航顶掉（P1）
① 点「今天/收件箱」等同于点「离开当前浮层」：任何打开的复盘、项目进度、记录、周期、结账浮层都会被关掉，标签直接切过去。② 复盘、项目进度、记录、周期四个浮层右上角的关闭控件由纯图标改成「图标 + 关闭」字样，看得见、点得到。

### US4 — 归类时直接在列表里长出新项目/新标签（P2）
归类浮层里，项目与标签各自在已有条目的最后放一个虚线 `+`；点它原地变成一个输入框，回车即建即选，Esc 取消。
**Why this priority**：原来的固定输入框让「我只想选一个」的常见动作多扫一行，且看起来像必填。

### US5 — 总览能钻到明细，并能换三种看法（P2）
① 鱼骨每根骨、进度条每行都可点，展开该步骤下「还没做完的」任务明细（可勾可改，用同一行组件）。② 总览新增三种视图：鱼骨、进度条、清单，随时切换；三者读同一份数据。③ 每根骨/每行直接标出「N 件没做」或「都做完了」。
**Why this priority**：「有几件没做」只有数字没有名字时，用户还得跑去树形里找。

### 边界情况

- 分组里的项目恰好被删掉：分组头退化成「未归项目」，不显示箭头。
- 项目里一个步骤都没有：三种总览都显示空态提示，切换不报错。
- 步骤下任务全做完：`+` 明细显示「都做完了」，不显示空列表。
- 归类浮层里项目/标签都为空：`+` 仍然可用，先建再选。
- 项目面板里勾掉一个任务：面板与首页同时更新；任务若被删，行从面板消失。
- `+` 输入框回车建重名：沿用既有 `stats.nameTaken`；Esc 关闭不创建。
- 停在复盘页时点「收件箱」：浮层关闭且列表切到收件箱。

## 需求

- **FR-001**：首页每个按项目分组的头 MUST 提供一个可直接进入项目进度页的入口，并自动选中该项目。
- **FR-002**：未归项目的分组 MUST NOT 提供该入口。
- **FR-003**：项目进度里列出的任务 MUST 使用与首页相同的行组件（勾选、改名、右击菜单、截止日期与项目/标签徽标）。
- **FR-004**：项目进度 MUST 在任务被修改后重新读取该项目的任务，用户无需手动刷新。
- **FR-005**：点击「今天」「收件箱」标签 MUST 关闭所有已打开浮层后再切页。
- **FR-006**：复盘、项目进度、记录、周期四个浮层 MUST 提供带文字的关闭控件。
- **FR-007**：归类浮层的项目与标签列表 MUST 在末尾提供内联新建入口（`+`），点击后在原位展开输入框。
- **FR-008**：内联新建 MUST 沿用既有的校验与重名规则，回车提交、Esc 取消。
- **FR-009**：总览 MUST 支持「鱼骨 / 进度条 / 清单」三种视图，且三者基于同一份数据。
- **FR-010**：总览中的步骤 MUST 可展开查看其未完成任务明细，明细可直接勾选或编辑。
- **FR-011**：总览 MUST 对每个步骤显示「N 件没做」或「都做完了」。
- **FR-012**：本 feature MUST NOT 新增 IPC 命令、数据库列或依赖；不改动既有浮层的数据加载逻辑。

## 成功标准

- **SC-001**：从首页分组头点到项目进度页 ≤ 1 次点击，且进入后当前项目正确。
- **SC-002**：项目面板里可执行的操作集合与首页一致（勾选、改名、改日期、设 DDL、挂/摘步骤、移到明天、回收件箱、删除）。
- **SC-003**：浮层打开时点标签，100% 能切页，无需先关闭。
- **SC-004**：四个浮层的关闭控件包含可读文字。
- **SC-005**：归类浮层新建项目/标签的点击次数从 3 次（点输入框、输入、点创建）降到 2 次（点 `+`、输入回车）。
- **SC-006**：总览三种视图切换无报错、数据一致（同一项目下未完成件数相同）。
- **SC-007**：门禁全绿：`vue-tsc` 0 error、clippy 0 warning、`gate.ps1` 10 PASS、`check-i18n` 成对。

## 增补 2026-11-10 15:10：去重与统一框架

- **分组头只留一个动作**：删掉分组头右侧的跳转箭头（与名字跳转重复，还挤占了件数的位置）。现在折叠靠左侧下箭头，跳转靠点项目名（悬停下划线 + `title` 提示），件数靠右对齐。
- **统一浮层框架**：新增 `src/components/PanelShell.vue`（标题 + 副标题 + `actions` 插槽 + 右上角带文字的「✕ 关闭」+ 单一滚动区），`StatsSheet.vue` / `HistorySheet.vue` / `ProjectSheet.vue` / `RecurringSheet.vue` 全部改为复用。四个面板的标题字号、头部间距、关闭位置从此完全一致，关闭按钮带文字，不再是一个容易忽略的小图标。
- **总览去重**：鱼骨与进度条视图负责「结构 + 进度」，点选后在同一个明细区展示该步骤未完成的事；清单视图本身就是「所有没做的事按步骤分组」，因此在该视图下不再重复渲染明细区。
- 新增键 `home.expand` / `home.collapse`（折叠按钮的无障碍标签），删除未再使用的 `home.toProject`；`check-i18n` 为 345 = 345。
