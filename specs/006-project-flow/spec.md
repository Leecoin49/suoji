# Feature Specification: 006 项目节点链

**Feature Branch**: `006-project-flow`
**Created**: 2026-11-09
**Status**: 实现中
**Input**: 用户原话：「项目可以支持像流程图或者思维导图的功能，方便跟进，比如一个节点做完了，进入下一个节点，节点可编辑。」（005 的姊妹篇，见 `specs/005-project-tags/spec.md` 决策记录 D2）

## 为什么单独成篇

005 交付了「项目」这个实体与「归类」这件事；本 feature 只解决**一个项目内部的推进节奏**。两者分开的理由写在 005 的 D2：

1. 它依赖 `projects` 表先存在，没法和 005 并行落地；
2. 「节点」有自己的生命周期（完成、重开、改名、删掉、排序），规则独立于归类；
3. 宪法 I 明令禁止「看板/甘特视图、子任务树」，这个 feature 必须逐条证明自己不是那些东西（见「不可破坏的不变量」）。

## Clarifications

### Session 2026-11-09

- Q: 节点图要不要可以自由拖拽、连线、分行分列？ → A: 不要。**线性链路**：一条竖直的步骤链，按 `sort_order` 排列；「当前节点」= 第一个没完成的节点，由数据推导，不存字段。理由：拖拽与自由布局正是宪法 I 点名禁止的「拖拽排序/看板视图」，而用户要的是「下一步是什么」。
- Q: 一个节点完成之后要不要自动生成下一个？ → A: 不自动。完成只是打勾，下一个自然变成「当前」；用户仍可随时在链尾追加。理由：自动生成会往用户库里写他没写过的文字。
- Q: 节点能不能挂任务、能不能有截止日期？ → A: 都不能。节点只有标题、可选备注、完成状态、顺序。挂任务就变成「子任务树」，那是另一条禁令。
- Q: 项目在 005 里可以归档，归档后节点还看得到吗？ → A: 看得到但只读呈现（项目胶囊以删除线显示）。归档是「不做了」，不是「删掉」。

## 用户故事

### US1（P1）一条链走到底

一个正在推进的项目，我打开「项目进度」，看到从上到下的步骤；做完一步就打勾，链上那一步变浅并划掉，下一步自动变成「当前」。**Why this priority**：这是本 feature 的全部价值 —— 让「接下来做什么」不需要重新想一遍，单独交付即可用。

### US2（P2）节点可以随时改

写错了、顺序变了、这一步多余了：点标题改名、hover 出删除、勾错了可以重开。**Why this priority**：不改就废 —— 一次写对的步骤链不存在，但它依赖 US1 的链路先存在。

### US3（P3）多项目之间切换

顶部项目胶囊列出全部项目（归档的置灰），点一下就换链；没有项目时能就地建一个。**Why this priority**：单项目场景下 US1 已闭环，多项目只是让 005 的项目实体真正可用。

## Edge Cases

- 项目一个节点都没有：显示「还没有步骤」+ 先写第一步的引导，不显示空进度条。
- 全部节点都完成：显示「这一串走完了」，不把最后一个节点标成「当前」。
- 标题只有空格：拒绝，提示与项目名同一套（空 / 超长）。
- 标题超长（> 60 字）：拒绝并提示上限。
- 备注为空：不渲染备注行，不留空白占位。
- 删除中间节点：后面的节点保持原顺序（`sort_order` 留空洞不影响排序）。
- 同一个项目被两个窗口同时改：后一次读到的结果覆盖界面（命令都返回完整链，天然收敛）。
- 项目被归档后新增节点：允许（归档只是标记），但胶囊显示删除线。
- 项目被删除：005 只支持归档，故链不会孤儿化。
- 节点命令失败：在面板顶部显示与复盘面板同一句失败文案，不弹窗、不清空已有链。

## Requirements

### Functional Requirements

- **FR-001** 系统 MUST 提供「项目进度」面板，从标题栏进入，Esc 关闭。
- **FR-002** 系统 MUST 在一个面板内按 `sort_order` 升序展示所选项目的全部节点。
- **FR-003** 系统 MUST 把第一个未完成节点标记为「当前」，且该标记由数据推导而非存储。
- **FR-004** 系统 MUST 允许对节点打勾完成、取消完成，且界面在同一次交互后刷新整条链。
- **FR-005** 系统 MUST 允许在链尾追加节点，并拒绝空标题与超过 60 字的标题。
- **FR-006** 系统 MUST 允许就地修改节点标题与备注，空标题视为放弃修改。
- **FR-007** 系统 MUST 允许删除任意节点，删除后其余节点顺序不变。
- **FR-008** 系统 MUST 展示「已完成 / 总数」进度，并在全部完成时给出整串完成提示。
- **FR-009** 系统 MUST 允许在面板内切换项目，归档项目以可辨识的样式呈现。
- **FR-010** 系统 MUST 允许在面板内新建项目，并复用 005 的重名与长度校验。
- **FR-011** 系统 MUST 在节点为空、全部完成、命令失败三种状态下给出可区分的呈现。
- **FR-012** 系统 MUST 让节点的所有写操作在失败时保留界面现状并给出可读提示。

### Key Entities

- **Node（节点）**：`id`、`projectId`、`title`、`note`、`done`、`sortOrder`、`createdAt`、`updatedAt`。属于一个项目，不跨项目共享。
- **Chain（链）**：某项目节点的有序集合，由 `sort_order` 决定；链上「当前」位置是派生量。
- **Progress（进度）**：`已完成数 / 总数`，全部完成时为满。

## Success Criteria

- **SC-001** 用户从标题栏打开「项目进度」到看见步骤链不超过 1 次点击，且无加载闪烁。
- **SC-002** 打勾一个节点后，链上状态、进度数字、「当前」标记三者同时更新，用户无需刷新。
- **SC-003** 追加 / 改名 / 删除各一次操作后，重新打开面板看到的顺序与操作后一致（持久化正确）。
- **SC-004** 空项目、全部完成两个极端状态各有一句明确的文案，不出现空进度条或错误标记。
- **SC-005** 标题长度上限与空标题校验在保存前生效，不会写入空节点。
- **SC-006** 切换项目不超过 1 次点击，切换后面板内容整体替换而非叠加。
- **SC-007** 归档项目在胶囊列表中以删除线呈现，仍可点开查看。
- **SC-008** 节点写操作失败时，界面保留原链并在顶部给出提示，不出现半截更新。
- **SC-009** 该 feature 不新增任何图表/拖拽依赖，`pnpm-lock.yaml` 与 `Cargo.toml` 改动行数为 0。
- **SC-010** 全流程离线可用，不发起任何网络请求。
- **SC-011** 中英双语下节点相关文案不出现裸 key。

## 兼容边界

**冻结（不可改）**：

- 既有 23 条 IPC 命令名与 `Task`/`DayView`/`Settings`/`StatsRaw`/`Project`/`Tag` 的字段名（本 feature 只新增 5 条节点命令与 2 个类型）。
- `capabilities/default.json` 的 15 项权限不变（节点通过既有 SQLite 能力读写，不新增文件/网络权限）。
- 005 的项目语义：项目只归档不删除；项目名按 `lower(trim(name))` 去重。
- 复盘面板的区间语义、桶规则、推后榜口径。
- `parseCapture` 的一句话录入契约与顺延（rollover）规则。

**新增**：`list_nodes` / `save_node` / `delete_node` / `complete_node` / `reopen_node` 五条只碰 `nodes` 表的读写命令，均返回整条链；`Node` / `NodeInput` 两个 camelCase 类型。

## 数据影响

- 有 DDL，但**不加列**：新增 `nodes` 表与 `idx_nodes_project(project_id, sort_order)`，并在 `db::MIGRATIONS` 里注册为 `MIGRATION_2`（对应 `schema_version = 2`）。
- 迁移：与 005 同一套机制 —— 单事务 `BEGIN IMMEDIATE`、按 `MIGRATIONS` 下标补跑、失败 `ROLLBACK`、迁移前自动复制 `suoji.db.pre-005`。
- 旧库能否直接打开：能。`nodes` 表对旧库是纯追加，`schema_version` 从 1 跳到 2 只跑 `MIGRATION_2`。
- 回滚：删除 `nodes` 表并把 `meta.schema_version` 置回 1 即可（`references/RUNTIME.md` 记录）。
- 行数变化：`tasks` / `meta` / `day_notes` 行数不变；`nodes` 初始 0 行。
- 本 feature 不产生任何历史数据改写（`done_at`、`roll_count`、`last_rolled_at` 都不碰）。

## 双语影响

新增 key（zh / en 成对，前缀 `nodes.`）：

`nodes.title`、`nodes.subtitle`、`nodes.pick`、`nodes.empty`、`nodes.emptyHint`、`nodes.add`、`nodes.placeholder`、`nodes.complete`、`nodes.reopen`、`nodes.delete`、`nodes.current`、`nodes.progress`、`nodes.allDone`、`nodes.note`、`nodes.notePlaceholder`，以及标题栏入口 `nav.projects`。

复用不新增：`stats.close`、`stats.error`、`history.loading`、`stats.newProject`、`stats.create`、`stats.nameEmpty`、`stats.nameTooLong`、`stats.nameTaken`。Rust 侧不新增任何面向前端的 `Labels` 文案（节点文案全在前端）。

## 不可破坏的不变量

- **宪法 I（一件事）**：本 feature 是「一条线性步骤链」，不是「看板视图」——无拖拽、无分列、无批量；也不是「子任务树」——节点不挂任务、不嵌套、不参与顺延与完成统计。判据：节点数据只在 `nodes` 表、只被 5 条节点命令读写；`tasks` 表不增加任何节点引用。
- **宪法 II（数据唯一副本）**：`nodes` 是节点的唯一副本；不引入任何影子状态（「当前节点」不落库、不缓存到 localStorage）。
- **宪法 III（本地优先）**：无网络、无账号、无新增依赖（SC-009/SC-010）。
- **宪法 IV（IPC 最小）**：5 条命令各一句 SQL 语义，全部返回整条链，避免前端推测状态；字段名靠 `serde(rename_all = "camelCase")`。
- **宪法 V（双语）**：15 个 `nodes.*` key 与本篇同时落地，缺 en 会直接显示 key 名（`t()` 的行为）。
- **锁纪律**：命令内 `Mutex<Connection>` 的 guard 只覆盖 SQL，返回前释放。

## 决策记录

- **D1 线性链而非自由图**：见 Clarifications Q1。
- **D2 当前节点是派生量**：不存 `current_node_id`，避免状态漂移；实现为「第一个 `done = 0` 的节点」。
- **D3 节点只有标题+备注**：加字段就滑向子任务树（宪法 I）。
- **D4 面板内可建项目**：如果只允许在归类浮层建项目，空库用户打开「项目进度」会无路可走。
