# Feature Specification: 项目变成三层树，首页按项目分组

**Feature Branch**: `007-project-tree`
**Created**: 2026-11-10
**Status**: Implemented

## 背景

006 把项目做成了「一条竖向步骤链」，005 让人能把任务归到项目。两件事各自成立，但它们是并列的：
在项目里看不到「哪一步下面有哪些事」，在首页也看不出今天这些事各属于哪个项目的哪一步。

用户提出（原文）：「项目进度中一个项目可以有多个步骤，每个步骤下的事情会有一个或者多个，
也就是说可以在一个项目中查看多个步骤下的多个任务，项目、步骤、任务都是支持点击可编辑以及
右击选择删除；同时对项目整体提供一个总览的功能，可以考虑使用鱼骨图等清晰展示的方案。」
「首页日常的任务在创建后也归类一下，同一个项目中同一个步骤的任务在同一个标签下，支持收缩功能。」

## 用户故事

### US1（P1）一个项目里看见每一个步骤下面的每一件事

- **Why this priority**：这是「跟进一个项目」的核心动作。没有它，步骤链只是一张进度条，
  事情散在首页，用户得自己在脑子里拼。
- 场景：打开「项目进度」→ 选项目 → 看到 N 个步骤，每个步骤下挂着属于它的任务（可勾选完成）。
  步骤没有任务时显示「0 件事」，不隐藏步骤。
- 场景：在某一步下就地新建一件事——回车即建，落在当前项目 + 当前步骤。
- 场景：任务挂在项目下但没挂步骤 → 出现在「没挂步骤的事」区块，仍然可见可勾。

### US2（P2）三级都能就地改名、右击删除

- **Why this priority**：树一旦有三层，改错名字和删错对象的成本就上去了；没有一致的编辑手势，
  用户只能靠「先建一个再删旧的」绕路。
- 场景：点击项目名 / 步骤标题 / 任务标题 → 变成输入框；回车或失焦保存，Esc 放弃，空标题不写库。
- 场景：右击项目 / 步骤 / 任务 → 同一个菜单提供「改名」与对应的删除项。
- 场景：删除步骤时，它下面的事**不跟着删**，而是回到「没挂步骤的事」。

### US3（P3）一个项目的总览：鱼骨图

- **Why this priority**：树回答「有哪些」，鱼骨回答「卡在哪」。项目一长，树要滚很久。
- 场景：右上角「树形 / 总览」互切；总览里项目是脊背、步骤是刺，刺上标「没做完 / 共几件」，
  做完的刺变浅划线；右侧头部给出「完成 k/n」。

### US4（P1，首页）今天按「项目 · 步骤」分组并可折叠

- **Why this priority**：用户的原话是「同一个项目中同一个步骤的任务在同一个标签下，支持收缩」。
- 场景：首页今天列表按 项目 → 步骤 分组，每组一行小标题（项目名 · 步骤名 + 件数），点标题折叠/展开。
- 场景：没归项目的任务仍然垫底列出，且只有一组「没归项目」时不显示分组标题（不制造噪音）。

## 需求

- **FR-001** 项目进度面板提供「树形」与「总览」两种视图，默认树形。
- **FR-002** 树形视图按「项目 → 步骤 → 任务」渲染：每个步骤节点展示其标题、完成状态、任务数。
- **FR-003** 每个步骤下必须能就地新建任务，创建后该任务同时归属该项目与该步骤。
- **FR-004** 属于项目但未挂步骤的任务，集中在「没挂步骤的事」区块展示。
- **FR-005** 把任务挂到某步骤时，任务的项目必须与该步骤所属项目一致。
- **FR-006** 项目名、步骤标题、任务标题均可点击进入编辑；空标题或未改动不写库。
- **FR-007** 项目、步骤、任务均可通过右键菜单改名与删除；删除步骤不得删除其下的任务。
- **FR-008** 删除项目时，其下任务回到未分类，步骤一并删除，任务本身不删。
- **FR-009** 总览视图必须以鱼骨形式展示：项目为脊背、每个步骤一根刺、刺上标注未完成数与总数。
- **FR-010** 总览视图须给出该项目的完成比例（已完成步骤 / 总步骤）。
- **FR-011** 首页今天列表按「项目 → 步骤」分组，组内保持后端顺序。
- **FR-012** 每个分组标题可折叠，折叠状态仅存活于当前会话，不写库。
- **FR-013** 未归项目的任务在首页列在最后一组；只有一组且无项目时不显示分组标题。
- **FR-014** 所有新增文案必须中英成对，缺一即缺陷。
- **FR-015** 本 feature 不新增写路径到统计面板；`get_stats` 契约不变。
- **FR-016** 不做拖拽排序、不做任意深度嵌套、不做多选批量；层级固定三层。

## 成功标准

- **SC-001** 打开任一带步骤的项目，一次滚动内可看到某步骤下的全部任务（≤10 条时无需二次点击）。
- **SC-002** 在步骤下新建一件事，从回车到出现在该步骤下 ≤ 1 次交互（无二次确认）。
- **SC-003** 三级改名均可在 1 次点击 + 1 次回车内完成。
- **SC-004** 删除步骤后，其下任务数量不变，且全部出现在「没挂步骤的事」。
- **SC-005** 右击菜单在窗口右/下边缘仍完整可见（不溢出屏幕）。
- **SC-006** 总览视图在 10 个步骤时无需横向滚动即可看到全部刺（默认窗宽 760）。
- **SC-007** 首页分组在 20 条任务、5 个组时，折叠/展开无卡顿（< 100 ms 视觉响应）。
- **SC-008** 中英文案键成对（`check-i18n` PASS）。
- **SC-009** `vue-tsc --noEmit`、`cargo clippy -D warnings`、`gate.ps1` 全绿。
- **SC-010** 迁移后旧库可直接打开，`tasks` 行数不变。
- **SC-011** 首页不分组时（全部未归项目）视觉与上一版一致。

## 兼容边界

- 既有 32 条 IPC 全部保留；本 feature 只新增 `set_task_node`，共 33 条。
- `Task` 结构体只**新增**可空字段 `nodeId`；既有字段名与语义不变（`serde` camelCase 不变）。
- 既有命令签名不变：`list_nodes` / `list_project_tasks` / `save_node` / `delete_node` 的入参出参不变。
- 统计面板（`get_stats`、`StatsRaw`）不新增字段、不改口径。
- `capabilities/default.json` 不新增权限。
- 顺延规则、录入解析、结账语义不变。

## 数据影响

- DDL：`ALTER TABLE tasks ADD COLUMN node_id TEXT`（带存在性判断）+ `CREATE INDEX idx_tasks_node`；`schema_version` 2 → 3。
- 不迁移数据、不改写任何既有行；旧任务 `node_id` 为 NULL，表现为「没挂步骤」。
- 迁移前自动复制 `suoji.db.pre-005`；单事务，失败回滚。
- 回滚方式：删除 `node_id` 列不可行（SQLite），实际回滚 = 用备份替换；应用降级到旧版本时该列被忽略。
- 行数不变；旧库可直接打开。

## 不可破坏的不变量

- 宪法 I（v1.1.0）：层级固定三层，不得出现第四层、拖拽排序、多选批量。
- 宪法 II：迁移只增列，不改写用户行；破坏性操作必须用户显式确认。
- 宪法 IV：IPC 只经 `api.ts`；新增命令必须在 `lib.rs` 与 `api.ts` 同时落地。
- 宪法 V：文案成对，`t()` 缺键会把 key 名显示给用户。
- 删除步骤不得删除任务；删除项目不得删除任务（spec 005 D6′）。
