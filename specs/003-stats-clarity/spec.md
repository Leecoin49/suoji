# Feature Specification: 复盘面板的可读性重做

**Feature Branch**: `003-stats-clarity`

**Created**: 2026-11-09

**Status**: Draft

**Input**: User description: "感觉看板有点粗糙，请从资深产品经理的角度分析一下，一个看板应该具备哪些功能。"

## Clarifications

### Session 2026-11-09（评审前定稿）

- **范围只做「看得懂」**：结论句、可读的图、断档与最值标注、悬停、点击下钻、明细按天分组折叠、空/稀疏引导、口径脚注、键盘可达。**不做**时段分布、星期分布、完成率、双序列环比（属 004「答得上」），**不做**复制/导出/写日记（属 005），**不做**标签/项目维度（属 006，需 `schema_version` 迁移）。
- **下钻与分组都在前端内存完成**：`getStats` 已返回区间内全量明细，因此本 feature **不新增 IPC、不改 `StatsRaw`**；筛选只是一个视图层谓词。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 打开就是一句结论，不用自己算 (Priority: P1)

用户点开复盘面板，第一眼看到的是人话结论而不是一堆数字：这段时间做了多少、比上一段多还是少、节奏上有什么异常（最忙的一天、断档的那天）。想深究时再往下看数字与图。

**Why this priority**: 这是「粗糙」的主因——现在的面板要求用户自己从 30 行横条里读结论。只完成这一条，面板就已经从「统计列表」变成「能看一眼的结论」，可独立交付价值。

**Independent Test**: 造一份含 90 天、200 条完成记录、其中 1 天为 0 件、1 天为最高值的库，打开面板即可看到结论句；结论句里的每个数字都能在下方的数字区与明细里找到出处。

**Acceptance Scenarios**:

1. **Given** 库里有 62 件完成、上一段 48 件、最高一天 9 件、中间断 1 天，**When** 打开复盘面板（默认 30 天），**Then** 首屏第一行是一句结论，同时含「62 件」「比上一段多 12 件」「最忙一天 9 件」「断过 1 天」这四个事实。
2. **Given** 上一段完全没有数据，**When** 打开面板，**Then** 结论句降级为「这期间做完 62 件，暂无可比区间」，不出现 0 件差，也不出现空白或占位符。
3. **Given** 区间内 0 件完成，**When** 打开面板，**Then** 结论句位置显示空态文案，而不是「0 件，持平」这类噪声结论。

---

### User Story 2 - 图要能看出形状，柱子要能点进去 (Priority: P2)

用户看到的时间分布不再是一列 6px 高的细条：有 0 基线、有竖直方向的最大值刻度，最高的一天有标注、断档的那天看得出来；鼠标悬停任一段都有「这段时间是什么时候、几件、占多少」；点某一段就只看那一段的明细，再点一次取消。

**Why this priority**: 只有结论句时，用户想问「哪一天最忙」还得自己数。图可读 + 可下钻，才算是「看得出来」，但它依赖 US1 的数据口径，因此排在 P1 之后。

**Independent Test**: 用同一份数据，逐桶悬停核对「日期范围 + 件数 + 占比」；点第 3 个桶后明细条数等于该桶件数，再点一次恢复全量。

**Acceptance Scenarios**:

1. **Given** 30 天区间内有 30 个天桶、最高 9 件，**When** 悬停任意一个桶，**Then** 立即显示该桶的起止日期、件数、占区间总数的百分比；0 件的桶显示「0 件」，不留空提示框。
2. **Given** 最高值与断档同时存在，**When** 看分布图，**Then** 最高桶有可辨识的标注、0 件的桶以区别于「有值但很小」的形态呈现，且 0 基线可见。
3. **Given** 用户点了 11-03 那一段，**When** 查看明细区，**Then** 明细只剩该段内的条目，并显示「已筛选：11-03」与「清除」入口；再次点击该段恢复全量。
4. **Given** 处于筛选状态，**When** 用户切换到 90 天，**Then** 筛选自动清除，不残留上一个区间的日期。

---

### User Story 3 - 明细能翻，键盘能用，数据少时说人话 (Priority: P3)

明细按天分组，默认只展开最近 5 天，其余折叠；面板内可用键盘操作（Tab 走一圈、Esc 关闭、focus 环可见）；数据很少时给出「再记几天就能看趋势」这类具体引导，而不是一片空白。

**Why this priority**: 这些是「精致度」问题，缺了不影响主线结论，但直接决定体感是否粗糙。

**Independent Test**: 200 条明细时首屏只渲染 5 组且可逐组展开；只用键盘可完成打开→切区间→下钻→关闭；0 件 / 1 天 / 1 件三种库各打开一次，文案各不相同且都指向下一步动作。

**Acceptance Scenarios**:

1. **Given** 区间内有 40 天有数据，**When** 打开明细区，**Then** 默认展开最近 5 天、其余以「还有 N 天」折叠，展开任一组不改变上方任何统计数字。
2. **Given** 面板已打开，**When** 只用 Tab / Shift+Tab / Enter / Esc 操作，**Then** 能到达预设区间、自定义日期、每个桶、折叠开关与关闭按钮，且每一步都能看到 focus 环。
3. **Given** 库里只有 1 件完成，**When** 打开面板，**Then** 显示「目前只有 1 件有完成时刻的记录」并提示如何积累到可看趋势，MUST NOT 复用「记录」页的空态文案。

---

### Edge Cases

- **单日区间**（自定义开始日 = 结束日）：只有一个桶，刻度与标注不得因「只有一个值」而消失或错位；当天 0 件时是空态 + 一个 0 桶。
- **周桶与月桶的下钻**：91–365 天按周、> 365 天按月时，点击某周/某月桶筛选的是该桶被裁剪后的起止日，而不是完整自然周/月。
- **未标注完成时刻的行**（`done_at` 为空）：没有日期可归组，固定放在明细末尾的独立分组，不参与按天分组，也不参与下钻筛选。
- **同一天条目很多**（如一天 40 件）：该组内再折叠（默认 10 条），折叠不改变计数。
- **区间结束日 = 今天**：最后一天不完整（今天还没过完），必须与完整日区别呈现，避免用户误读为「今天效率低」。
- **悬停与键盘焦点并存**：键盘 focus 优先于鼠标 hover 的提示，两者不得同时出现两个提示框。
- **窄窗口**：窗口收窄到最小宽度时，刻度、标注与数值不得被裁掉或换行错位。
- **语言切换**：中英切换后结论句、刻度、占比、筛选提示全部随之重算，不残留另一语言的文本。
- **筛选 + 空结果**：筛选到某天但那天在明细里恰好只有未标注完成时刻的行，需要给出「这一天没有留下完成时刻」而不是空白。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 视图 MUST 继续保持**只读**：结论句、悬停、下钻、分组展开、键盘操作的全过程 MUST NOT 新增/修改/删除任何任务，也不得触发顺延或结账。
- **FR-002**: 视图首屏 MUST 在第一屏内容的最上方给出一句**结论**，内容由三部分组成：完成量（件数）、与上一等长区间的比较（多/少/持平/无可比）、节奏异常（最忙一天与断档天数，缺一项则省略该项）。三者 MUST 都能在下方数字区或明细里找到出处。
- **FR-003**: 结论句 MUST 与其它展示同源：同一区间下，结论句中的件数 MUST 等于「这期间做完」的展示值，MUST 等于明细条数加未标注完成时刻的小计。
- **FR-004**: 结论句 MUST NOT 出现空值痕迹：任一组成项无数据时 MUST 使用专门的降级文案（如「暂无可比区间」「这期间没有断档」），MUST NOT 出现 `NaN`、`Infinity`、`undefined`、`null`、裸露的 key 名或空的标点占位。
- **FR-005**: 时间分布 MUST 是可读的图形而不只是进度条：MUST 有可见的 0 基线与竖直方向的量纲刻度（至少 3 档：0、中间值、最大值），MUST 标注最高的那一段，MUST 让 0 件的段与「有小值」的段在形态上可区分。
- **FR-006**: 每个时间桶 MUST 支持悬停查看「该段起止日期、件数、占区间总数的百分比」；0 件的段 MUST 显示明确的 0 件文案，MUST NOT 出现空提示。
- **FR-007**: 用户 MUST 能点击任一时间桶把明细筛选到该段范围，界面 MUST 显示当前筛选范围与清除入口；再次点击同一段 MUST 取消筛选；切换区间或自定义日期时 MUST 自动清除筛选。
- **FR-008**: 明细 MUST 按天分组并显示每组的件数；默认只展开最近 5 个有数据的组，其余以「还有 N 天」折叠；展开/折叠 MUST NOT 改变任何统计数字。
- **FR-009**: 明细中 `done_at` 为空的完成任务 MUST 归入末尾独立分组并标注「未标注完成时间」，不分摊到任何一天，也不参与下钻筛选。
- **FR-010**: 空态与稀疏态 MUST 分档：0 件、仅有 1 天数据、仅有 1 件、无推后记录各有独立文案与下一步动作提示；MUST NOT 复用会让人误以为「页面出错」的通用空态文案。
- **FR-011**: 面板 MUST 支持纯键盘操作：打开后焦点进入面板内第一个可操作元素；Tab / Shift+Tab MUST 能在预设区间、自定义日期、每个时间桶、折叠开关、关闭按钮之间循环；Esc MUST 关闭面板；被聚焦元素 MUST 有可见的 focus 环。
- **FR-012**: 面板底部 MUST 固定一行口径说明，覆盖三件事：推后次数是**累计**、积压是**此刻实时值**、未标注完成时刻的行如何计入；该说明 MUST 可折叠且默认收起为一行。
- **FR-013**: 区间结束日为今天时，最后一天 MUST 有不完整标记（例如「今天还没过完」），避免被读成效率下降。
- **FR-014**: 本 feature MUST NOT 引入图表库或任何新运行时依赖；图形 MUST 用既有渲染能力与既有设计 token 实现，颜色与字号 MUST 复用现有 token，不新增主题色。
- **FR-015**: 新增/改写的每一条用户可见文案 MUST 在中英两侧同时存在，占位符集合一致；日期、百分比、刻度数字 MUST 随界面语言格式化。
- **FR-016**: 入口、关闭方式、与其它 sheet 的互斥行为 MUST 与既有实现一致（`TitleBar.vue` 的图表按钮 → `Esc`/关闭按钮退回「今天」），MUST NOT 新增独立窗口或第二入口。

### Key Entities

- **结论（Conclusion）**：由完成量、环比、节奏异常三部分组成的单句；不是新数据，而是既有聚合结果的叙述化表达。
- **时间桶（Axis bucket）**：区间被切分后的最小展示单位（日/周/月），带起止日期、件数、是否为区间内的最大值或 0 值、是否被裁剪。
- **明细分组（Day group）**：同一天完成的条目集合，含件数与展开状态；另有一个「未标注完成时间」的末尾分组。
- **筛选（Filter）**：由点击某个时间桶产生的明细范围约束，只在视图层生效，不落库、不跨区间保留。
- **口径说明（Footnote）**：对累计推后、实时积压、未标注完成时刻三条口径的固定解释，避免用户误读。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 让 1 位目标用户打开面板后不说话地看 10 秒，随后能正确回答「最忙的是哪几天」与「中间断过没有」，2 项全对；无需滚动页面。
- **SC-002**: 结论句自洽：对 7 / 30 / 90 与 2 个自定义区间共 5 个区间，结论句中的件数、数字区的总数、明细条数与未标注小计之和三者相等（差值 0）。
- **SC-003**: 悬停完整率：对区间内**每一个**时间桶（含 0 件桶）悬停，都能读到「日期范围、件数、占比」三段信息，缺信息或空提示的桶数量为 0。
- **SC-004**: 下钻正确率：抽取 5 个时间桶逐个点击，筛选后明细条数与桶件数相等（差值 0），其中 1 次为 0 件桶且显示「这一段没有完成记录」。
- **SC-005**: 稀疏态覆盖：0 件 / 1 件 / 仅 1 天数据三种库各打开一次，文案互不相同且各含下一步动作提示，出现 `NaN`/`undefined`/裸 key 的次数为 0。
- **SC-006**: 键盘可达：从面板打开到关闭，仅用键盘完成「切到 90 天 → 下钻第一个桶 → 取消筛选 → 折叠一组明细 → 关闭」，全程 0 次鼠标操作；Tab 可达的可聚焦元素 ≥ 8 个，每一步都有可见 focus 环。
- **SC-007**: 双语完整度：zh/en 切换后面板内裸露 key 数为 0；`check-i18n.ps1` 输出 PASS，两侧键数相等。
- **SC-008**: 性能不退化：10 000 条任务 / 365 天区间下，切换区间到画面稳定 ≤ 500 毫秒（重复 5 次取中位数），且与 002 已测的耗时相比不增加超过 100 毫秒。
- **SC-009**: 只读性：打开 → 悬停若干桶 → 下钻 3 次 → 展开/折叠 3 次 → 关闭，前后数据库文件字节大小与 `tasks` / `meta` / `day_notes` 行数变化为 0。
- **SC-010**: 零新依赖：`package.json` 依赖段与 `pnpm-lock.yaml` 的改动行数为 0；`src-tauri/Cargo.toml` 依赖段改动行数为 0。
- **SC-011**: 视觉一致性：与「记录」面板对比，新增颜色 token 数量为 0，字号种类不超过既有面板已用的 5 档。

## Assumptions

- 「粗糙」的根因是**信息层级与图形**，不是数字口径；002 已定稿的口径（预设 N 天含今天共 N 个桶、累计推后、实时积压、未标注单列）在本 feature 中一律**不改**。
- `getStats` 已返回区间内全量明细，故下钻、分组、折叠、悬停占比都可以在视图层完成，不需要新的查询命令，也不需要新字段。
- 时间桶的绝对数量有上界（≤ 90 天时为天桶，91–365 为周桶、> 365 为月桶），因此「每桶一个可聚焦元素」在键盘循环上是可接受的：90 个天桶时 Tab 一圈较长，但配合分组折叠仍可用。
- 用户是单人、本机、不联网；数据规模 ≤ 50 000 条；不存在多端同步或权限差异。
- 中文为默认语言，英文同等公民；文案不依赖机器翻译占位。
- 本 feature **不做**分类/标签维度：那需要给 `tasks` 加列并在 `schema_version` 落地后才能做（宪法 II），已单独立项等待 F003。

## 兼容边界

- IPC 命令集 MUST 保持 **17 条不变**：本 feature 不新增、不改名、不改参数类型；`get_stats` 的 `(start, end)` 签名与 `StatsRaw` 的字段名、顺序、可空性 MUST 逐字冻结。下钻与分组 MUST NOT 通过新增查询参数实现（否则等于改契约）。
- `src/lib/api.ts` 的 `api.getStats` 与 `src-tauri/src/model.rs` 的 `StatsSpan` / `DoneEntry` / `RollEntry` / `StatsRaw` MUST NOT 变；若实现中发现字段不够，MUST 停下来先改 spec，MUST NOT 现场加字段。
- 002 已定稿的区间语义 MUST NOT 变：预设 N 天 = `today−(N−1)` 至 `today`（N 个桶）；自定义区间含首尾；结束日超过今天按今天封顶并提示；≤ 90 天按日、91–365 按自然周、> 365 按自然月；首末桶按区间边界裁剪；各桶之和等于「有完成时刻」小计。
- 推后榜口径 MUST NOT 变：入榜条件为区间内 `last_rolled_at` 落在区间且 `roll_count > 0` 且未删除，展示**累计**次数并注明「累计」；排序规则（次数倒序 → 最近推后日倒序 → 创建时间 → id）MUST NOT 变，以保证同一份数据多次打开顺序一致。
- 「记录」页（`list_done_history`）的签名与「近 N 天、新→旧」语义 MUST NOT 变；本 feature MUST NOT 改造它来承接新交互。
- 既有 i18n key MUST NOT 重命名、删除或重排；本 feature 只能新增 key，或在**语义完全相同**时复用既有 key。
- `src-tauri/capabilities/default.json` MUST 保持 15 项，不增不减；MUST NOT 引入剪贴板、文件读写、对话框等新权限（复制/导出属 005）。
- 入口与窗口行为 MUST NOT 变：仍是 `TitleBar.vue` 的一个图标按钮与面板内关闭，`Esc` 退回「今天」，与其他 sheet 互斥；MUST NOT 新增窗口、托盘项、快捷键或拖拽分列。
- 视觉语言 MUST 复用既有面板形态（`bg-paper` / `bg-card` / `text-ink` / `accent` / `line` / `warn` 等 token 与 `scroll-thin` 滚动条），MUST NOT 引入新的设计体系或第二套字号。

## 数据影响

- **DDL：无。** 不加表、不加列、不加索引；`tasks`（15 列）/ `meta` / `day_notes` 原样。
- **迁移：无。** 不读写 `schema_version`，不依赖 F003 落地。
- **写入：0 行。** 悬停、下钻、折叠、键盘操作 MUST 全部是视图状态；MUST NOT 写 `meta` 保存筛选或展开状态（刷新/重开回到默认）。
- **查询面：不变。** 仍只调用一次 `get_stats`，不发第二次查询；不新增 `SELECT`，不改既有 `SELECT`。SC-009 是这条的机器可验证形式。
- **内存行为**：下钻筛选与按天分组在已取回的数据上进行；区间上限对应的条目数受「区间内完成件数」约束，口径与 002 相同，不引入新的内存增长点。
- **行数不变**：打开、悬停、下钻、折叠、关闭前后，三张表行数变化 MUST 为 0。
- **回滚**：还原 `StatsSheet.vue`、回滚新增 i18n key 与帮助文案即可完全恢复；无数据遗留、无 schema 残留。
- **不可重建项**：逐日积压快照、时段分布所需的分组字段（如标签）在库中不存在，本 feature MUST NOT 伪造，也不得为此加列。

## 双语影响

- **新增 `stats.*` key（zh / en 成对，占位符集合一致，MUST 同批提交）**：
  - 结论层：`stats.conclusion`（`{n}` 件数）、`stats.conclusionPrevUp`（`{n}`）、`stats.conclusionPrevDown`（`{n}`）、`stats.conclusionPrevFlat`、`stats.conclusionPrevNone`、`stats.conclusionPeak`（`{d}`、`{n}`）、`stats.conclusionGap`（`{n}`）、`stats.conclusionNoGap`
