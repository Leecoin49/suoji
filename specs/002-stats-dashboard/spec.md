# Feature Specification: 复盘统计（Review Stats）

**Feature Branch**: `002-stats-dashboard`

**Created**: 2026-11-06

**Status**: Draft

**Input**: User description: "加一个统计看板的功能，可以统计出一段时间内做过的任务，方便复盘。"

## Clarifications

### Session 2026-11-06

- Q: 「推后最多」榜里那个次数，是展示累计推后次数（含区间外的历史）并明确标注为「累计」，还是根本不展示次数？ → A: 展示 `roll_count` 并明确标为「累计推后 N 次」；榜单入榜条件是 `last_rolled_at` 落在区间内，并附「最近推后 M月D日」作为入榜依据。MUST NOT 把累计次数说成区间内次数（库里无逐次推后日志，不可重建）。
- Q: 「连续多少天有完成」这个数，是只在所选区间内数（数到区间起点为止就停），还是允许越过区间起点继续向前追溯？ → A: 只在区间内数。锚点取「今天」与「区间结束日」中较早者，锚点日 0 件则为 0；MUST NOT 越过区间起点追溯，因此上限 = 区间天数。
- Q: 复盘视图从哪里打开（且关闭后回到哪里）？ → A: `src/components/TitleBar.vue` 新增一个图表图标按钮，与 `nav.history` / `nav.help` / `nav.update` 并列；沿用现有「一次只开一个 sheet」互斥逻辑，关闭或 Esc 后回「今天」。入口只有这一个，不在记录页里再嵌入口。
- Q: 「自定义」区间要不要封顶天数（比如最长 365 天），还是允许任意长并自动聚合成周/月？ → A: 不设上限。≤ 90 天按日、91–365 天按自然周、> 365 天按自然月自动聚合；聚合后时间桶个数等于该粒度下的自然段数，桶内之和 MUST 仍等于有完成时刻的总数。
- Q: 「近 30 天」是按 30 个天桶（今天往前数 30 天，含今天），还是与「记录」页 HistorySheet 完全同窗（today−30 到 today，共 31 个日历日）？ → A: 30 个天桶：预设 N 天 = `today−(N−1)` 至 `today`，天桶数 = N；SC-002 改为「同一对起止日期下，统计的「有完成时刻小计」与记录页明细条数差 0」，不再要求与 `list_done_history` 的 `since = today − 30` 窗口相等（该窗口是 31 个日历日，既有实现不改）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 选一段时间，看清楚这期间做完了多少事 (Priority: P1)

用户周日晚上想回顾这一周：打开「复盘」，默认落在近 30 天，看到这段时间**完成的总件数**、**按天排开的每日件数**（没完成的那天也有一根空条），以及**逐条完成明细**（标题 + 完成时刻，新→旧）。她换到「7 天」或「90 天」，同一屏的数字整体重算；月底复盘时她选「自定义」，把起止日期填成 10-01 到 10-31，看整个月。

**Why this priority**: 这是「复盘」唯一不可替代的切面。今天她只能在「记录」页里按天滚动、靠脑子数；`HistorySheet.vue:12` 的 7/30/90 只给了清单与「共 N 件」，没有分布、没有横向比较。
P1 因为它**只读、不改任何表列、不写任何行**，一次成型即可交付价值，风险最低。

**Independent Test**: 在一个有 120 条跨 60 天完成记录的库上，打开复盘视图 → 默认 30 天：总数、可 30 个天桶、明细三块同时出现且数字自洽（把 30 个天桶相加 == 「有完成时刻小计」== 明细条数；总数 = 有完成时刻小计 + 「未标注完成时间」小计）；切到 7 天与 90 天，三块数字同步变化。

**Acceptance Scenarios**:

1. **Given** 库里有 30 天内完成的任务，**When** 用户打开复盘视图且不改区间，**Then** 显示近 30 天总件数、30 个连续的天桶（含 0 件的那天）、以及按完成时刻倒序的明细。
2. **Given** 复盘视图停在 30 天，**When** 用户点「7 天」，**Then** 总数、天桶数量（7）、明细条数三者同步改为近 7 天的口径，页面不出现上一个区间的残留数字。
3. **Given** 某天的任务是在本地时间 00:30 勾掉的，**When** 统计按天归属，**Then** 它算在**那一天**，而不是前一天（本地日期切分，不做 UTC 换算）。
5. **Given** 用户选择「自定义」，**When** 填入 10-01 到 10-31，**Then** 天数显示 31、天桶 31 个、总数等于该月完成件数，且明细不越界（9-30 与 11-01 完成的任务不出现）。
6. **Given** 用户把开始日期填成晚于结束日期，**When** 提交，**Then** 显示「开始日期不能晚于结束日期」且不发起查询、不返回空列表、不静默交换两值。
4. **Given** 库里有 `done = 1` 但完成时刻为空的历史行，**When** 统计近 30 天，**Then** 这些行单列在「未标注完成时间」下并被计入总数，而「有完成时刻小计」与「记录」页同一对起止日期的条数完全一致（见 FR-011 / SC-002）。

### User Story 2 - 看出「哪些事老是没做完」 (Priority: P2)

同一屏的下半部分回答第二个问题：这段时间里**被推后最多的 5 件事**（标题 + 推后次数）、**平均每天完成几件**、**截至今天连续多少天有完成**，以及**此刻还没做完的件数**（并注明是「此刻」而不是区间末尾的历史快照）。

**Why this priority**: 复盘的一半价值在「我完成了什么」，另一半在「什么总在往后挪」——宪法里「挪过 5 次 / 挂了 12 天」的意图（`src/lib/i18n.ts` 的 `content.zh.why`）今天只在单条任务上有提示，从没有跨时间的汇总。
P2 依赖 P1 的同一份区间数据，可独立验收；没有它，P1 仍然是一个能用的「完成数看板」。

**Independent Test**: 造一个库：A 推后 6 次且 `last_rolled_at` 在区间内，B 推后 6 次但 `last_rolled_at` 在区间外，C 推后 2 次在区间内，其余为 0。视图的「推后最多」恰好列出 A 与 C（不含 B），且显示为「累计推后 6 次 / 2 次」并附最近推后日期，顺序稳定；平均每天 = 「有完成时刻小计」÷ 区间天数（保留 1 位小数）；连续天数在某天 0 件处断开且不越过区间起点。

**Acceptance Scenarios**:

1. **Given** 区间内有若干被推后过的未删除任务，**When** 打开复盘，**Then** 按累计推后次数降序展示前 5 条并写明「累计推后 N 次」与「最近推后 M月D日」；不足 5 条时展示实际条数，0 条时显示「这段时间没有推后的事」。
2. **Given** 两条任务推后次数相同，**When** 连续打开复盘 5 次，**Then** 它们的先后顺序 5 次完全一致（并列时有确定的排序键，不依赖查询返回顺序）。
3. **Given** 区间内没有任何一天完成过任务，**When** 打开复盘，**Then** 平均每天显示 0.0、连续天数显示 0，不出现 NaN、Infinity 或空白。
4. **Given** 用户正在看统计，**When** 她离开去勾掉一条任务再回来，**Then** 「此刻还没做完」的数字减少 1，且页面标注该数字是实时值。

### User Story 3 - 和上一个等长区间比一比 (Priority: P3)

用户想回答「这周比上周多做还是少做了」。视图在总数旁给出与**上一个等长区间**的差值（+12 件 / −3 件 / 持平），点一下可以展开上一区间的同口径数字。

**Why this priority**: 单个区间的绝对数字无法回答「在变好还是变差」，而复盘的动作本质是横向比较。它纯读、只多一个聚合口径，实现上复用 P1/P2 的全部窗口逻辑。
P3 因为它没有它也不影响「看完了多少」，属于把复盘从「数数」推到「判断」的那一步。

**Independent Test**: 造一个库：近 7 天完成 10 件、前 7 天完成 7 件。视图显示「+3 件」；把前 7 天里 3 件的完成时刻改到近 7 天，重开视图显示「持平」。

**Acceptance Scenarios**:

1. **Given** 近 30 天完成 40 件、前 30 天完成 52 件，**When** 打开复盘，**Then** 对比区显示「−12 件」，且展开后能看到上一区间的总数。
2. **Given** 两个区间件数相同，**When** 打开复盘，**Then** 显示「持平」，不显示 `+0` 或 `−0`。
3. **Given** 区间起点之前没有任何数据（首次使用第 5 天），**When** 打开复盘，**Then** 对比区显示「没有可比较的上一个区间」，不把缺失数据当成 0 件。

---

### Edge Cases

- **空库**：一件都没完成过 → 总数 0、每个天桶 0、明细空态；平均 0.0、连续 0、对比区「暂无可比区间」；不得出现 NaN、Infinity、除零报错、空白图表。
- **只有一天有数据**：连续天数 = 1；平均每天 = 该天件数 ÷ 区间天数（下限 1 天），不是 ÷ 1。
- **开始日 == 结束日**：区间为 1 天，含当天完成的全部任务；天数显示 1，不显示 0。
- **开始日晚于结束日**：拒绝查询并提示「开始日期不能晚于结束日期」，不得静默交换或返回空列表。
- **结束日晚于今天**：MUST 封顶到今天再做除法，并提示已封顶；不得把未来空白天计入分母把平均值压低。
- **跨年区间**（12-25 → 01-05）：天桶按时间正序跨越年份，不得把 1 月的天排到 12 月之前，天数 = 12。
- **超长区间**（365 天以上）：自动切为按周 / 按月聚合（FR-018），总数、明细、推后榜口径 MUST 不变；聚合后的桶 MUST 仍按时间正序且含 0 值段，不得因为桶变少而丢掉跨年区间的排序。
- **连续天数上限**：只在区间内数，数到区间起点就停（即使区间外还有完成记录），显示值永不大于区间天数。
- **已删除（`deleted = 1`）任务**：MUST NOT 进入任何统计（总数、天桶、明细、推后榜、积压）。
- **未完成任务**：MUST NOT 进入完成数；只进入「推后榜」（若在区间内被推后过）与「此刻还没做完」。
- **完成时刻为空的历史行**：计入总数、单列「未标注完成时间」，不进天桶、不进连续天数。
- **跨零点**：本地时间 23:59 与 00:01 完成的两件算在相邻两天（按本地日期切分）。
- **区间边界含首尾**：区间起点当天 00:00 与终点当天 23:59 完成的都算在内，不得出现「差一天」。
- **推后次数并列**：用确定的次级排序键（最近推后时间，再任务创建时间，再 id），保证多次打开顺序一致。
- **语言切换**：复盘开着时切到英文，全部文案与日期/数字格式同步切换，0 个 key 名裸露。
- **区间切换过快**：连续快速点 7/30/90，最终画面必须与最后一次选择一致，不得出现旧区间数字覆盖新区间。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供一个只读的「复盘」视图；打开、切换区间、展开对比、关闭的全过程 MUST NOT 新增/修改/删除任何任务，也不得触发顺延或结账。
- **FR-002**: 视图 MUST 提供预设区间 7 / 30 / 90 天并默认 30 天；MUST 另提供「自定义」起止日期；每次打开视图 MUST 回到默认 30 天，MUST NOT 把上次区间持久化到任何存储。区间 MUST 含首尾两天，天数 = 结束日 − 开始日 + 1。**预设 N 天的口径 MUST 是 `today−(N−1)` 至 `today`，即天桶数恰为 N**（30 天 = 今天及之前 29 天，共 30 个桶）；MUST NOT 采用 `since = today − N` 的「多一天」窗口。
- **FR-017**: 自定义区间 MUST 校验：开始日晚于结束日时拒绝并提示，不发起查询；结束日晚于今天时按今天封顶并提示；跨年区间按时间正序排列，天数按实际日历日计算（含闰年 2-29）；MUST NOT 对区间总天数设上限，超长区间由 FR-018 的聚合粒度兼顾可读性。
- **FR-018**: 时间分布粒度 MUST 由区间天数决定：≤ 90 天逐日桶、91–365 天逐自然周桶（以本地周一为周首）、> 365 天逐自然月桶；首桶与末桶 MUST 按区间边界裁剪（首桶只统计区间起点及之后，末桶只统计到区间结束日）；每桶 MUST 可显示 0 值；**所有桶之和 MUST 等于「有完成时刻」的总数**。
- **FR-003**: 视图 MUST 显示区间内完成件数，归属日期按**本机本地日期**判定；MUST NOT 使用 UTC 或任何会跨零点错位的换算。
- **FR-004**: 视图 MUST 显示区间内完成件数的时间分布，按时间正序排列，**无完成的段显示 0 而不是省略**，使趋势不断档。粒度 MUST 按区间天数自动选定：**≤ 90 天按日、91–365 天按自然周、> 365 天按自然月**（见 FR-018）。
- **FR-005**: 视图 MUST 显示区间内完成明细（标题、完成时刻），按完成时刻倒序；有备注的任务 MUST 可展开看备注。
- **FR-006**: 视图 MUST 显示区间内被推后过的未删除任务中推后次数最高的前 5 条（标题 + 次数）；区间判定依据是该任务在本区间内有过推后动作。**展示的次数 MUST 是任务的累计推后次数（`roll_count`，含区间外的历史推后），且 MUST 在文案上写明是「累计」，MUST NOT 让用户读成「区间内推了这么多次」**；同时 MUST 展示该任务的最近推后日期（`last_rolled_at`）作为区间归属的依据。
- **FR-007**: 视图 MUST 显示平均每天完成件数 = 「有完成时刻小计」÷ 区间天数（分母不用含未标注完成时间的总数，避免抬高均值），保留 1 位小数；天数 MUST ≥ 1，结果 MUST NOT 为 NaN/Infinity。
- **FR-008**: 视图 MUST 显示截至今天（或区间结束日，取较早者，以下称锚点日）连续「每天 ≥ 1 件完成」的天数；某天为 0 即中断；无数据时为 0。**统计 MUST 只在所选区间内进行，数到区间起点即停，MUST NOT 越过区间起点向前追溯**；因此结果上限为区间天数（每天都完成时等于区间天数），MUST NOT 返回大于区间天数的值。
- **FR-009**: 视图 MUST 显示**此刻**未完成且未删除的任务件数，并以用户可读的方式标明这是实时值而非区间末尾的历史快照。
- **FR-010**: 视图 MUST 显示与上一个等长区间的完成件数差（+/−/持平）；上一个区间完全没有数据时 MUST 显示「暂无可比区间」，而不是 0 件差。
- **FR-011**: 视图 MUST 把「完成时刻为空但已完成」的历史行单列为「未标注完成时间」并计入总数。**总数的内部口径 MUST 拆为两个小计：有完成时刻小计 + 未标注完成时间小计；只有前者与「记录」页同一区间的明细条数逐条一致（差值 0，见 SC-002）**，后者 MUST NOT 被当成 0 件丢弃，也 MUST NOT 被强行猜一个完成时刻。
- **FR-012**: 空态 MUST 覆盖：0 件完成、0 件推后、无可比区间；所有数值型展示在空态下为 0 或空文案，MUST NOT 泄露 `NaN`、`Infinity`、`undefined` 或裸露的 key 名。
- **FR-013**: 区间切换 MUST 以最后一次选择为准；从发起到画面稳定 MUST ≤ 500 毫秒（库内任务 ≤ 10 000 条、区间 ≤ 365 天）。
- **FR-014**: 视图 MUST 在断网、无任何外部资源（字体、CDN、图表 SDK）的情况下完整可用。
- **FR-015**: 视图 MUST 从主界面**唯一入口**打开：`src/components/TitleBar.vue` 标题栏右侧与「记录 / 帮助 / 更新」并列的一个图表图标按钮（tooltip 用 `nav.stats`）；打开时 MUST 关闭其他 sheet（与 `openHistory` 同构的互斥逻辑），MUST NOT 新增独立窗口；可用 Esc 或关闭按钮退回「今天」，退回后「今天」页的数据与打开前完全一致。
- **FR-016**: 视图新增的每一条用户可见文案 MUST 在中英两侧同时存在，占位符集合一致；日期与数字格式 MUST 随界面语言变化。

### Key Entities

- **完成记录（Completion record）**：一条「某任务在某本地时刻被完成」的事实。属性：任务标识、标题、备注、完成时刻、由此得到的本地日期、顺延次数。来源只有既有的 `tasks.done` / `done_at`，本 feature 不新增采集。
- **统计区间（Reporting period）**：一对本地日期（含首尾）+ 天数 + 上一个等长区间的同构描述。是视图一切数字的唯一口径来源。
- **天桶 / 周桶 / 月桶（Time bucket）**：区间内的一个本地日期（或自然周、自然月）+ 该段的完成件数（可为 0）。粒度由区间天数决定（≤90 日 / 91–365 周 / >365 月，见 FR-018）。**全部桶之和 MUST 等于总数中的「有完成时刻」部分**。
- **推后条目（Rollover entry）**：区间内被推后过的未删除任务 + **累计**推后次数（`roll_count`，含区间外历史）+ 最近推后时间（`last_rolled_at`，同时是入榜依据）。本条目的次数**不是**区间内次数——库里没有逐次推后日志，视图 MUST NOT 把它说成区间内次数。
- **实时积压（Current backlog）**：此刻未完成且未删除的任务数。**不是**历史快照——库里没有逐日快照，视图 MUST NOT 假装有。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从主界面到看见 30 天统计结果，MUST 在 2 次点击以内、3 秒以内完成（含冷启动后首次打开）。
- **SC-002**: 总数口径一致性：对**同一对起止日期**，统计「有完成时刻小计」与「记录」页明细条数差值 MUST 为 0（用含 200 条完成记录、其中 5 条无完成时刻的库验证）；若拿“总数”去比，差值 MUST 恰等于「未标注完成时间」条数，而不是任意值。该断言 MUST 在「自定义」区间与 7 / 30 / 90 预设上各验证一次；由于「记录」页的预设窗口是 `since = today − N`（N+1 个日历日）而统计预设是 N 个天桶，两者在预设上的原始计数**允许差一天**，比对 MUST 以相同起止日期为准，MUST NOT 声称两者恒等。
- **SC-003**: 时间桶完整性：**天数 ≤ 90 时 MUST 一个日历日一个桶且数量恰等于天数（7→7、30→30、90→90）**；91–365 天时 MUST 一个自然周一个桶（含首末裁剪周）；> 365 天时 MUST 一个自然月一个桶；缺段数 MUST 为 0，且各桶之和 MUST 等于有完成时刻的总数（差值 0）。
- **SC-004**: 空库下 MUST 有 0 个 `NaN` / `Infinity` / `undefined` 文本出现，0 条控制台报错。

## Assumptions

- 「复盘」= 对**已完成**与**被推后**的既有事实做只读聚合；不新增任何采集字段，不引入打点、不引入「目标/计划完成数」这类新概念。
- 完成时刻的既有格式是本机本地时间 `YYYY-MM-DDTHH:MM:SS`（无时区后缀，见 `src-tauri/src/commands.rs:16` 的 `now_iso`），因此按前 10 个字符切本地日期即可，不需要时区换算。
- 库里**没有**逐日积压快照（`tasks` 只有当前状态 + `roll_count` / `last_rolled_at`），所以「区间末尾的积压」不可重建。本 feature 只展示实时积压并明确标注；新增快照表属于数据类 feature（依赖 F003 的 `schema_version`），不在本 feature 范围。
- 「统计看板」的「看板」是**只读聚合面板**，不含拖拽、分列流转、批量勾选、子任务树；宪法 I 禁止的「看板/甘特视图」指的是可拖拽的分列任务看板。该读法已由 D1 定稿，本 feature 不触发宪法修订。
- 区间给 7 / 30 / 90 三个预设（与 `HistorySheet.vue:12` 一致）+「自定义」起止日期；默认 30 天，且**不持久化**上次选择（不写 `meta`，因此不产生任何写入）。
- 不引入图表库或任何新运行时依赖；用既有 Tailwind 排版 + 简单条形呈现，符合「栈冻结」。
- 不引入测试框架（宪法「测试现状」条款：测试属独立 feature）；若 `001-parse-contract` 已先引入，则统计口径的纯计算部分应补对应契约用例。
- 导出 / 复制为文本不在本 feature（`CONTRIBUTING.zh-CN.md:92-96` 与 F004 的导出格式仍未决策）。
- 预设区间的天数口径已由澄清定稿：N 天 = 今天及之前 N−1 天，共 N 个天桶。既有的「记录」页（`list_done_history`，`since = today − N`，N+1 个日历日）**保持原样不改**，因此两者在同一预设下的原始件数可能相差一天；这是预期差异，不是缺陷，比对口径以「同一对起止日期」为准（见 SC-002）。
- 单用户、单机、数据量级 ≤ 50 000 条任务（个人记事 5 年量级）；并发写入只有用户自己的勾选动作。
- 中文为默认语言，英文同等公民；不依赖机器翻译占位。

## 决策记录（原待澄清，已于评审前定）

- **D1｜宪法 I 的「看板」边界** → 采纳「视为只读面板，不改宪法」。判据写死为：**出现拖拽、分列流转、批量勾选即为越界；静态聚合 + 只读列表不在禁止范围**。因此本 feature 不触发宪法修订，但实现时 MUST NOT 引入任何可拖拽的分列形态。
