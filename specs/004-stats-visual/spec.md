# Feature Specification: 复盘面板的视觉重排（日历热力图 + 指标卡）

**Feature Branch**: `004-stats-visual`

**Created**: 2026-11-09

**Status**: Draft

**Input**: User description: "复盘统计模块的UI再优化一下，参考市面上的主流产品。"

## 背景

002 解决了「有数据可看」，003 解决了「看得懂」。但面板的视觉仍是自制小工具的样子：细柱条没有坐标系、四个次级指标挤在一张描述列表里、切换区间时整块硬跳。用户的原话是「有点粗糙」，这次要求按市面上主流产品的视觉语言重排。

参考对象及取舍：GitHub 贡献图（日历矩阵表达「一段时间做了多少」）、Linear 的排版与留白（信息层级靠字号和间距，不靠分割线）、Apple 屏幕使用时间与 WakaTime 的指标卡（四个问题各占一块，扫读一致）。**照搬布局、不照搬功能**：不加分享、不加目标设定、不加导出（后者仍等 F004 决策）。

## Clarifications

### Session 2026-11-09

- Q1 → A: 视觉基调 = **GitHub 贡献图 + Linear 排版**。单色系强调、细密网格、深留白、靠字号建立层级（不用分隔线堆叠）。
- Q2 → A: **天档（≤90 天）主视图换成日历热力图**（7 行 × N 列，一格一天，颜色深浅表示件数）；**周档（91–365 天）与月档（>365 天）保持柱图**（保留刻度线、峰值徽标、今天标记）。
- Q3 → A: 数字区改为**四张等宽指标卡**（平均每天 / 连续天数 / 环比上一段 / 此刻积压），每张 = 主数值 + 标签 + 一句补充。
- Q4 → A: **克制的过渡动效**——区间切换 150ms 淡入（上限 200ms）、悬停反馈 ≤100ms；系统开启「减少动态效果」时全部归零。
- Q5（推定，未占用提问名额）→ A: 0 件区间**仍显示热力图骨架**（全中性格），而不是换成一张空态卡——「一片空白」本身就是这段时间的结论，比换文案更诚实；结论句与引导文案叠加在骨架之上。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一眼看到这段时间的节奏 (Priority: P1)

用户打开复盘面板，天档下看到的是一张日历矩阵：每一格是一天，颜色越深那天做得越多，空白格就是那天什么都没完成。他不需要读任何数字，就能说出「10 月底那周最密」「11 月初断了四天」，然后点一下某一格，明细就只剩那天的事。

**Why this priority**: 这是本次唯一「换骨」的部分，也是「粗糙」感受的主要来源。单独交付它（其余保持 003 现状）面板就已经明显更专业，MVP 成立。

**Independent Test**: 只做热力图与结论句，不改指标区与动效，即可验收：矩阵行列对齐、5 档配色、今天与峰值可辨、点击下钻。

**Acceptance Scenarios**:

1. **Given** 区间为最近 30 天且其中 18 天有完成记录，**When** 打开面板，**Then** 显示 7 行 × 5 列（含首末列补齐空格）的日历矩阵，有记录的日子按件数落在 4 档色阶之一，无记录的日子为中性底色。
2. **Given** 矩阵已显示且今天在区间内，**When** 观察今天所在格，**Then** 该格有独立的「今天」标记，且标记在只靠颜色时也能被识别。
3. **Given** 存在某天件数最多，**When** 观察该格，**Then** 该格带形状标记（描边或角标），并列最多的多天都被标注。
4. **Given** 矩阵已显示，**When** 点击 10/29 那格，**Then** 明细只列 10/29 的条目，标题写明筛选到哪天；**When** 再次点击同一格，**Then** 筛选取消、明细恢复全部。
5. **Given** 鼠标悬停在某格，**When** 停留超过 0.2 秒，**Then** 出现提示框，含该日日期、件数、占区间完成总数的比例，且提示框不超出面板左右边界。

---

### User Story 2 - 四个问题各占一块，扫读一致 (Priority: P2)

用户想知道「平均每天做了多少」「连着做了几天」「比上一段是多了还是少了」「现在手里还压着多少」。这四件事现在是挤在一张两列描述列表里的小字，读起来要一行行找。改后每块一张等宽卡片：大字是数值，小字是标签，再下一行一句补充。

**Why this priority**: 提升的是读表效率，不改变信息内容，所以排在热力图之后；但它决定面板「像不像专业产品」。

**Independent Test**: 只替换指标区布局，图表与明细不动，仍可独立验收。

**Acceptance Scenarios**:

1. **Given** 区间内有完成记录，**When** 打开面板，**Then** 四张等宽卡片同排（窄窗口下折成 2×2），每张含主数值、标签、一句补充。
2. **Given** 上一段区间为 0 件，**When** 观察环比卡，**Then** 主数值显示「—」与解释文案，不出现 NaN 或无穷大。
3. **Given** 积压数大于 0，**When** 观察积压卡，**Then** 该卡带「实时」标注，与其余三张的区间统计属性在视觉上可区分。

---

### User Story 3 - 切换不抖，悬停有回应 (Priority: P3)

用户从 30 天切到 7 天，再到 90 天，希望看到的是「内容变了」而不是「整块闪一下再长出来」。悬停到柱或格上，希望立刻有回应。同时他不希望这些花活拖慢低配机器。

**Why this priority**: 属于打磨层，缺失时不影响可用性，但它是「精致」与「粗糙」的分界线；放在最后，因为它依赖前两块的结构先稳定。

**Independent Test**: 只加过渡与悬停反馈，其余不动，录制切换过程即可验收。

**Acceptance Scenarios**:

1. **Given** 面板已显示 30 天，**When** 切换到 7 天，**Then** 新内容在 150ms 内淡入，图表容器高度不变，不出现空白帧。
2. **Given** 快速连点 7/30/90 三次，**When** 切换结束，**Then** 画面无残留动画、无叠加的半透明层，最终内容与最后一次点击一致。
3. **Given** 系统已开启「减少动态效果」，**When** 切换区间，**Then** 过渡时长为 0，内容直接替换。

---

### Edge Cases

- **区间只有 1 天**：只有一格有色，其余格为空；图例与指标卡仍完整。
- **起止不在周一/周日**：首列与末列出现区间外的空格，这些格不可点击、不参与悬停与键盘导航。
- **跨年区间**：矩阵可到 53 列；月标签在列头按月份出现，不因跨年错位。
- **今天是区间的最后一天且还未过完**：今天格有「今天」标记，色阶按已记录的件数计算，不做「按比例折算」这种假精确。
- **区间内 0 件完成**：矩阵显示全中性骨架 + 结论句（空态语义）+ 一句引导；不换成整块空态卡片，也不复用「记录」面板的空态文案。
- **只有未标注完成时刻的记录**：矩阵全中性，另有一条「另有 N 件没留完成时间」的提示，数量不为 0 时不隐藏。
- **某天件数极多（如 20 件）**：落在最高档并显示形状标记，图例最高档写「≥7」而不是写死上限。
- **窄窗口**：面板最小宽度下不出现横向滚动；格子随列数自适应（7 天档更大、90 天档更小），最小可点区域不小于 12×12。
- **色盲/低对比**：「今天」「峰值」「0 件」三者除颜色外必须有形状或位置差异。
- **连续快速切换区间**：迟到的响应不得覆盖较新的结果，动画不得叠加。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 区间为天档（≤90 天）时，主视图 MUST 为日历热力图；周档（91–365 天）与月档（>365 天）MUST 保持柱图；两种视图 MUST 复用同一份按时间分桶的数据，不得出现两套口径。
- **FR-002**: 热力图 MUST 为 7 行 × N 列，行固定为周一至周日，列为一个自然周；每列从周一起排；超出区间的格子 MUST 留空且不可交互。
- **FR-003**: 每格代表一个日历日；颜色 MUST 分 5 档：0 件为中性底色（非纯白，边界可见），其余 4 档为 1 件、2–3 件、4–6 件、≥7 件。
- **FR-004**: 热力图下方 MUST 有图例：5 个色块 + 「少 … 多」两端文案，配色与格子一致，最高档文案为「≥7」。
- **FR-005**: 区间内的「今天」MUST 有独立标记（描边或角标），并在图例或注释中说明该标记的含义。
- **FR-006**: 区间内件数最多的日子（含并列）MUST 有形状标记，不得只靠颜色深浅表达。
- **FR-007**: 点击格子 MUST 把明细筛选到那一天；再次点击同一格 MUST 取消筛选；点击区间外的空格 MUST 无反应。
- **FR-008**: 悬停格子 MUST 显示该日日期、件数与占区间完成总数的比例；提示框 MUST NOT 溢出面板左右边界。
- **FR-009**: 键盘 MUST 可完成全部格间操作：Tab 进入图表只占一个焦点位，方向键在格子间移动（左右跨日、上下跨周），Home/End 跳到区间首末，Enter/Space 执行下钻；当前焦格 MUST 有可见焦点环。
- **FR-010**: 指标区 MUST 为四张等宽卡片（平均每天、连续天数、环比上一段、此刻积压），每张含主数值、标签、一句补充说明；窄窗口下 MUST 折成 2×2 且不截断文字。
- **FR-011**: 数值不可用时（上一段为 0、无可用天数）主数值 MUST 显示「—」并附解释文案，MUST NOT 出现 NaN、Infinity 或空字符串。
- **FR-012**: 积压卡 MUST 标注「实时」，且与其余三张的「区间统计」属性在视觉上可区分。
- **FR-013**: 结论句 MUST 保留在面板顶部、图表之上，作为热力图/柱图的标题区；其语义与 003 一致，不得被图表取代。
- **FR-014**: 区间切换时新结果 MUST 以 150ms 淡入（上限 200ms）；切换过程中图表容器高度 MUST NOT 跳变；连续切换 MUST NOT 产生叠加或残留动画。
- **FR-015**: 悬停与焦点反馈 MUST 在 100ms 内出现；系统「减少动态效果」开启时，所有过渡时长 MUST 归零。
- **FR-016**: 视觉 MUST 只使用既有语义色板与既有字号档（与「记录」面板同一套），MUST NOT 新增颜色 token 或字号档。
- **FR-017**: 003 已交付的信息结构 MUST 不降级：明细按天分组折叠、口径脚注、稀疏五档空态、未标注提示、推后清单，均 MUST 保持可用。
- **FR-018**: 面板在最小宽度下 MUST NOT 出现横向滚动；格子随列数自适应，单个可点区域 MUST NOT 小于 12×12。

### Key Entities *(include if feature involves data)*

- **日历格**：一个日历日。属性：日期、当日件数、所属档位（0/1/2/3/4）、是否今天、是否峰值、是否区间外。区间外的格只有位置，没有数据。
- **热力图网格**：由日历格组成的矩阵。属性：行标签（周一至周日）、列数（自然周数）、每列起始日、首末列的空格数量。
- **指标卡**：一个被单独呈现的指标。属性：标题、主数值、补充说明、是否为实时值（只有积压是）、不可用时的替代文案。
- **图例**：5 档色块与两端文案的映射，供用户把颜色翻译回件数。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 首次打开面板的试用人，10 秒内能正确指出「最忙是哪天」与「中间断没断」，3 位试用人 3/3 正确。
- **SC-002**: 试用人能指出「哪一周最密」（列密度），3 位试用人 3/3 正确。
- **SC-003**: 四张指标卡在 560×720 窗口的首屏内全部可读，无需滚动。
- **SC-004**: 连续切换 7/30/90 各 3 次，可见高度跳变 0 次、空白闪烁 0 次（录屏复核）。
- **SC-005**: 纯键盘完成「移到某天 → 下钻 → 取消」≤10 秒。
- **SC-006**: 在色盲模拟下，「今天」「峰值」「0 件」三者仍可区分（形状标记存在），3 人核对 3/3。
- **SC-007**: 切换动效实测 150±50ms；系统「减少动态效果」开启时实测 0ms。
- **SC-008**: 003 验收通过的 11 条成功标准全部仍通过（无回退）。
- **SC-009**: 打开面板、切换区间、悬停、下钻之后，数据文件字节哈希与操作前一致，且面板不发出任何写操作。
- **SC-010**: 本次改动不新增任何依赖（依赖清单与锁文件改动 0 行），不新增图片或图标资源。
- **SC-011**: 打包后的脚本体积增幅 ≤ +8 kB（未压缩），不因视觉改动引入第三方图表实现。

## Assumptions

- 参考对象只取信息层级与克制风格，不照搬其功能（分享、目标、提醒、导出均不在本次范围）。
- 热力图只服务于桌面端固定宽度面板，不做移动端与响应式断点适配。
- 不引入图表库：宪法冻结了技术栈，且现有柱子/格子用基础样式即可表达。
- 数据维度不变：本次仍只有「完成时刻」一个维度，「一天中的时段」「星期偏好」不进入本 feature。
- 现有演示数据（288 条、覆盖 90 天）即可作为视觉验收集，不额外造数。
- 应用当前只有浅色纸感主题，深色模式不在本次范围。
- 「0 件仍显示骨架」是推定结论（见 Clarifications Q5），若验收时认为骨架在空数据下过于抽象，可在实现阶段改为骨架 + 更强引导，但不改回整块空态卡。

## 兼容边界

冻结、本 feature 不得改动：

- **IPC**：仍是 17 条，不新增命令；`StatsRaw` 的字段名与类型不变；`getStats(start, end)` 的入参不变。
- **纯函数**：002 的 8 个（`isIsoDay` / `validateRange` / `granularityOf` / `bucketize` / `maxCountOf` / `streakOf` / `compareOf` / `toView`）与 003 的 6 个（`conclusionOf` / `axisBucketsOf` / `axisTicksOf` / `sparsityOf` / `groupDoneByDay` / `filterEntries`）签名一律不变；允许新增纯函数（如热力图网格与档位计算），新增者必须无副作用、可断言。
- **口径**：002 的区间语义（含首含尾、`end` 超过今天则钳到今天）、推后榜口径（区间内被推后过 + 累计次数）、排序规则；003 的结论句三段结构与稀疏五档判定，均不变。
- **文案**：既有 `stats.*` 34 条 key 不删、不改语义；「记录」面板的 `history.*` 继续不得被复盘复用为空态。
- **权限**：`capabilities/default.json` 15 项不变。

## 数据影响

- **DDL**：0 条。不建表、不加列、不加索引。
- **迁移**：无。旧库直接打开即可，行数与字节规模不因本 feature 变化。
- **写入**：0 次。热力图、指标卡、档位、图例全部由既有 5 条只读查询的结果在内存中派生；筛选项、折叠状态、悬停状态一律不落库、不落本地存储。
- **回滚**：纯前端改动，回滚即还原组件与文案；数据层无任何需要回滚的痕迹。
- **风险**：唯一的数据风险是误改口径导致数字与 002/003 不一致 —— 由 SC-008 的回归与纯函数断言（既有 14 个函数的行为不变）挡住。

## 不可破坏的不变量

- **宪法 I（一件事）**：本次只做视觉重排。不得顺手加导出、分享、目标设定、自定义维度、把筛选状态持久化 —— 「拖拽/分列/批量」依然是越界判据。
- **宪法 II（数据唯一副本）**：0 写入、0 迁移。热力图与指标卡的生命周期只存在于一次渲染内。
- **宪法 IV（IPC 最小）**：不加命令、不加字段、不加权限；前端仍只经统一入口取数。
- **宪法 V（双语成对）**：新增 10 条 key 必须两侧同时落地；漏 en 会直接把 key 名显示给用户。
- **锁纪律**：本 feature 不碰 Rust，若实现中需要改 Rust 则说明方案错了，应停下重估。
- **不破坏既有断言**：`verify/lib_check.mjs`（46 条）、`verify/clarity_check.mjs` 必须继续全绿。

## 决策记录

- **D1 视觉语言 = GitHub 贡献图 + Linear 排版**（用户选定）。否决 Apple 屏幕使用时间风（大圆角大数字与窗口内其他浮层风格差异过大）与 WakaTime 风（面板 560px 宽下字号会被压到 10px 以下）。
- **D2 天档换热力图、周/月档保留柱图**（用户选定）。理由：柱图在 90 天以内尚可，但「密度与断档」用格子比用柱子更快看懂；周/月档列数太少，格子不如柱子直观。
- **D3 指标区改四张等宽卡**（用户选定）。理由：四个问题彼此独立，卡片化后扫读路径一致。
- **D4 克制动效 + 尊重「减少动态效果」**（用户选定）。否决逐柱生长与数字滚动（与记事工具的克制调性冲突，且会让连续切区间显得晃）。
- **D5 不引入任何图表库**（宪法栈冻结 + SC-010/SC-011）。热力图用基础样式排布，柱图维持 003 的样式实现。
